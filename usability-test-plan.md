# Usability Test Plan — Redesigned Learning Platform

## Purpose

The redesigned interface has passed technical browser, keyboard, responsive, and authorization verification. The next validation step requires real representatives of the centre’s audiences: a parent or guardian, an adult learner, and a member of the centre operations team. This document provides a repeatable moderated test so that actual feedback can be captured before operational records are introduced.

## Participant Tasks

| Participant | Scenario | Expected outcome | Observe |
|---|---|---|---|
| Parent or guardian | Find an appropriate programme and send an enrollment request. | Participant reaches programme guidance or enrollment without asking where to begin. | CTA comprehension, field clarity, confidence before sending. |
| Learner | Open the learning hub and find a timetable, material, teacher-support, payment, and report route. | Participant identifies the intended next action in each workspace state. | Label comprehension, navigation discoverability, relevance of empty-state explanation. |
| Centre operations | Open Founder console and locate learning operations, submissions, programmes, and announcements. | Participant understands which area manages each task without trial-and-error. | Sidebar comprehension, operational grouping, confidence in content publishing. |

## Facilitator Script

Ask participants to speak their thoughts aloud. Do not explain labels or point to controls. Record task completion, time to first action, error recovery, confidence on a 1–5 scale, and direct quotes. Ask: “What would you expect to happen next?”, “Was any wording unclear?”, and “What is missing for your daily task?”

## Technical Verification Completed

| Check | Result |
|---|---|
| Desktop and mobile layouts | Reviewed on 1280px and 390px viewports for public, learning, Founder login, and Founder operations areas. |
| Keyboard navigation | Six browser scenarios pass: skip link, programme discovery, filters, learning hub routes, enrollment validation, and protected-route redirect. |
| Accessibility foundations | Focus indicators, skip navigation, linked validation feedback, semantic landmarks, and reduced-motion behavior are implemented. |
| Authorization | Founder sign-in valid/invalid paths and protected route redirects are verified. |

## Completion Criteria

Proceed with operational data entry once every participant completes their core task unaided, no critical wording issue remains unresolved, and no user reports uncertainty about the next action. Any observed friction should be entered into the Founder’s redesign backlog, prioritized by impact, and retested with the affected participant type.
