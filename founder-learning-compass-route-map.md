# Founder Learning Compass — Route-by-Route Rebuild Map

| Route / component | Rebuilt internal surface | Learning Compass treatment | Functional contract retained |
|---|---|---|---|
| `Admin.tsx` / overview, submissions, announcements, content | Command header, tab strip, metric cards, review actions, tables and content forms. | Founder workspace header, shared rail, tonal metric cards, compact navigation controls and grouped data panels. | Route selection, submission status updates, announcement operations, operating hours and programme/team/testimonial CRUD. |
| `FounderOperations.tsx` | Operations pulse, five area selectors, active operation panel, ordered workflow, learning item form/list. | Route markers, action pills, two-column decision panels, verified-data empty state and status feedback surfaces. | Five operational areas, learning-item CRUD, validation and success/error states. |
| `FounderLearningData.tsx` | Data command header, learning-item editor/list and support-request inbox. | Confirm-and-publish header, structured form/list columns, semantic status feedback and responsive workspace surfaces. | Founder-only access, learning-item CRUD, request status updates, published learning-hub synchronisation. |
| `AnnouncementEditor.tsx` | Select-update list, edit form, publication action. | Shared command container, form/card treatment, editable list surface and accessible success/error presentation. | Founder access gate, selecting, editing and publishing verified announcements. |
| `DashboardLayout.tsx` and `FounderLogin.tsx` | Persistent navigation, responsive mobile header, sign-in form. | Learning Compass rail, compact mobile route header, secure minimal sign-in card. | Role guard, resize/collapse, navigation paths, logout, password-only sign-in. |

All routes consume the same `founder-workspace` and Learning Compass CSS rules for headers, sections, cards, data tables, inputs, state feedback and responsive navigation. The route-specific content is explicitly organised as overview metrics and command actions, operations area-selector and verified-data panels, learning-data editor/inbox panels, and announcement selector/edit panels. The concrete `FounderRouteSurface`, `FounderCommandHeader`, `FounderSegmentedNav`, `FounderMetricCard`, `FounderState` and `FounderPanel` components now render the protected route header, decision markers, readiness metrics, state cue and content canvas before each route’s existing data table and form sections. Final desktop and mobile captures confirm that this command surface remains readable across the Founder overview layout. This removes the prior route-level visual drift while leaving the existing procedures, ARIA semantics, confirmation dialogs and access control intact.
